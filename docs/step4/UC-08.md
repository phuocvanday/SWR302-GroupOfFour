| **UC ID and Name** | UC-08 — Check-in by QR |
| **Created By** | ngthien05 (Thiên) / completed for checklist by Phước |
| **Date Created** | 10/11/2026 |
| **Primary Actor** | Customer |
| **Secondary Actors** | QR Service |
| **Trigger** | Customer arrives at the gym entrance and starts Check-in by QR (scan membership QR at the gate reader / app). |
| **Description** | Customer checks in at the gym gate by presenting an ACTIVE membership QR. The system validates the QR, verifies membership status and opening hours, then records a successful check-in. |
| **Preconditions** | 1. Customer is authenticated (or presents a valid membership QR linked to an account). 2. Customer has a Membership with status **ACTIVE** and a linked QR token (BR-04). 3. Gate / QR reader (or phone camera) is available. |
| **Post conditions** | 1. On success: a CheckInLog entry is created with timestamp and membership ID. 2. Customer is allowed to enter. 3. On failure: no valid check-in is recorded; Customer remains outside / blocked with an error message. |
| **Normal Flow** | 1. Customer selects **Check-in by QR** (or presents QR to the gate scanner). 2. System prompts to scan the membership QR. 3. Customer presents the QR code. 4. System «include» **Validate QR Code**: sends payload to QR Service. 5. QR Service returns validation result. 6. System verifies membership is **ACTIVE** and within validity (BR-04). 7. System verifies current time is within gym open hours (BR-05). 8. System creates CheckInLog (membershipId, time, gate/location). 9. System displays check-in success (and opens gate if integrated). |
| **Alternative Flows** | 1. **Enter Code Manually** («extend» at extension point `ManualEntry`): At step 3, if the camera cannot scan, Customer/staff enters the membership code manually; System continues from step 4 with the typed code. 2. **Already checked in today (policy optional)**: System warns and asks to confirm duplicate check-in or blocks per gym policy. |
| **Exceptions** | 1. **Invalid / expired / inactive QR**: At steps 5–6, System rejects check-in and shows “Membership QR invalid or not ACTIVE” (BR-04). 2. **Outside open hours**: At step 7, System rejects check-in and shows open-hour message (BR-05). 3. **QR Service unavailable**: At step 4–5, System shows service error and does not record check-in; Customer may retry or use ManualEntry if enabled. |
| **Priority** | High |
| **Frequency of Use** | Very high at peak entry times (many check-ins per day). |
| **Business Rules** | BR-04: One valid QR only while membership is ACTIVE. BR-05: Check-in only during open hours and ACTIVE membership. |
| **Other Information** | Related: UCD Membership; SMD-01 Membership; Wireframe SCR-08. Supporting UC: Validate QR Code («include»); Enter Code Manually («extend»). |
| **Assumptions** | Gate clock is synchronized to UTC+7. QR token uniquely maps to one membership. |
