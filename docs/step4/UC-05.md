| **UC ID and Name** | UC-05 — Register Membership (at Counter) |
| **Created By** | vanxuanphuockar5@gmail.com (Phước) |
| **Date Created** | 10/11/2026 |
| **Primary Actor** | Gym Owner |
| **Secondary Actors** | Payment Gateway (optional online payment); Customer (provides personal data at the counter) |
| **Trigger** | A walk-in Customer requests a membership package at the counter, or the Gym Owner selects the function **Register Membership**. |
| **Description** | Gym Owner registers a membership for a Customer at the gym counter: identifies the Customer, selects a Membership Package, optionally applies a promo code, records payment (cash or Payment Gateway), and creates a membership with status **INACTIVE** until activation in UC-06. |
| **Preconditions** | 1. Gym Owner has successfully logged in (UC-02). 2. At least one Membership Package is available in the catalog. 3. Customer is present at the counter (or reachable) to provide registration data. |
| **Post conditions** | 1. A Membership record is created and linked to the Customer and selected package with status **INACTIVE**. 2. Payment information is recorded (paid in full or pending) according to the chosen method. 3. No membership QR is issued in this use case (QR is created only in UC-06). 4. If the use case fails, no **ACTIVE** membership exists for this registration. |
| **Normal Flow** | 1. Gym Owner selects **Register Membership**. 2. System displays the registration form and the list of available Membership Packages. 3. Gym Owner identifies the Customer (search by phone/email or enter new details: full name, phone, email). 4. System validates contact data format and shows whether the Customer already exists. 5. Gym Owner selects a Membership Package. 6. System calculates the payable fee and displays duration and total amount. 7. Gym Owner confirms the registration summary. 8. System creates a Membership record with status **INACTIVE**. 9. Gym Owner collects payment (records cash/transfer in GMS, or pays online via Payment Gateway — «include» **Process Payment** when gateway is used). 10. System records the payment result. 11. System displays success with Membership ID and prompts the Owner to continue with **Activate Membership (UC-06)** when the fee is fully paid. |
| **Alternative Flows** | 1. **Apply promo code** (extension point *PromoApplication*): At Normal Flow step 6, if the Customer has a promo code, Gym Owner enters the code; System validates it and recalculates the fee; resume at step 7. 2. **Existing Customer**: At step 4, if phone/email already belongs to a Customer, System shows the existing profile; Gym Owner confirms reuse; resume at step 5. 3. **Cash / offline payment only**: At step 9, if payment is cash or bank transfer confirmed offline, Gym Owner marks “Paid in full at counter” with a reference note; System stores payment without calling Payment Gateway; resume at step 11. 4. **Cancel before confirm**: At step 7, if Gym Owner cancels, System discards the uncommitted form and the use case ends with no new membership. |
| **Exceptions** | 1. **Payment Gateway failure**: At steps 9–10, if the gateway returns failure or timeout, System displays the error, keeps the membership **INACTIVE**/unpaid, and allows retry or end (BR-02). 2. **Persistence / system error**: At step 8, if System cannot save the membership, System displays an error and does not confirm success; the use case ends; Owner may retry later. 3. **Invalid or expired promo**: During Alternative Flow 1, if the promo code is invalid/expired, System rejects the code, keeps the original fee, and returns to step 6. |
| **Priority** | High |
| **Frequency of Use** | High during opening hours (multiple registrations per day at a busy site). |
| **Business Rules** | BR-01: Only an authenticated Gym Owner may register membership at the counter. BR-02: Membership must not become **ACTIVE** until the full package fee is recorded (activation is UC-06). |
| **Other Information** | Related diagrams: UCD Overview / Membership package; AD-03 (with UC-06). Wireframe: SCR-05 (Step 5). Supporting relations: «include» Process Payment; «extend» Apply Promo Code. Derived FRs: FR-05-01…FR-05-04. |
| **Assumptions** | Cash/transfer confirmation may be entered manually by the Gym Owner. Online Payment Gateway is optional. Customer contact data provided at the counter is accurate enough for later SMS in UC-06. |
