| **Primary Actor** | Personal Trainer |
| **Secondary Actors** | — (optional: SMS Service if customer notification is enabled) |
| **Trigger** | After a scheduled training session ends, the PT selects **Record Training Session** for a confirmed booking. |
| **Description** | Personal Trainer records that a training session under a Confirmed PT booking has been completed, decreasing remaining sessions and updating booking/session progress. |
| **Preconditions** | 1. PT is logged in with an **Approved** account (BR-07). 2. A PT booking exists with status **Confirmed**. 3. The booking still has unused sessions remaining (BR-10). 4. The session to record is on the training schedule (or ad-hoc allowed by policy). |
| **Post conditions** | 1. On success: TrainingSession is marked Completed; remaining session count decreases. 2. If remaining sessions become 0, booking may move to Completed (per SMD-02). 3. On failure: session counts unchanged. |
| **Normal Flow** | 1. PT opens **Training Schedule** / booking detail. 2. System lists Confirmed bookings and upcoming/past sessions for that PT. 3. PT selects the session (or booking) to record. 4. System shows session details (Customer, package, remaining sessions, scheduled time). 5. PT confirms **Record Session** (optionally adds notes). 6. System verifies booking is Confirmed and remaining sessions > 0 (BR-10). 7. System creates/updates TrainingSession as Completed and decrements remaining sessions. 8. System displays success and updated remaining count. |
| **Alternative Flows** | 1. **Customer no-show**: At step 5, PT marks session as No-show (if allowed); System records No-show instead of Completed and applies gym policy to remaining sessions. 2. **Edit notes after record**: PT updates notes only; status unchanged. 3. **Last session**: After step 7, if remaining = 0, System marks booking Completed and notifies Customer (optional SMS). |
| **Exceptions** | 1. **Booking not Confirmed / no remaining sessions**: At step 6, System blocks recording and shows BR-10 message. 2. **Unauthorized PT**: If PT is not the assigned trainer, System denies access. 3. **Persistence error**: System shows save failure; session remains unrecorded; PT may retry. |
| **Priority** | High |
| **Frequency of Use** | High — each completed PT session during operating hours. |
| **Business Rules** | BR-07: Only Approved PT may operate bookings/schedule. BR-10: Record only for Confirmed booking with remaining sessions. |
| **Other Information** | Related: UCD PT; SMD-02 PT Booking; Wireframe SCR-15; AD-01 (session side). |
| **Assumptions** | Schedule slots are created via UC-13 before recording, or gym allows record-from-booking without a prior slot. |
