| **UC ID and Name** | UC-12 — Confirm / Reject PT Booking |
| **Created By** | Nguyễn Anh Tuấn (Tuấn) |
| **Date Created** | 10/11/2026 |
| **Primary Actor** | Personal Trainer |
| **Secondary Actors** | SMS Service, Payment Gateway |
| **Trigger** | PT receives a new Pending booking notification, or opens **Manage PT Booking Requests**. |
| **Description** | An Approved Personal Trainer confirms or rejects a Pending PT booking within 24 hours. Confirm unlocks scheduling/session recording; Reject requires a reason and initiates refund when payment succeeded (BR-08, BR-09). |
| **Preconditions** | 1. Personal Trainer is authenticated. 2. PT account status is **Approved** (BR-07). 3. A `Pending` booking belongs to this PT. 4. Booking has not already expired/cancelled. |
| **Post conditions** | 1. **Confirm:** booking → `Confirmed`; Customer notified; booking eligible for schedule/sessions (UC-13/UC-15). 2. **Reject:** booking → `Rejected`; reason stored; Customer notified; refund initiated if paid. 3. On failure/validation error: booking status unchanged. |
| **Normal Flow** | 1. System notifies PT of a new Pending booking. 2. PT opens the Pending booking list. 3. PT selects a booking. 4. System shows Customer, package, preferred time, booking time, payment status, notes. 5. PT chooses **Confirm**. 6. System verifies booking still Pending, belongs to this PT, and is within 24h. 7. System sets status `Confirmed`. 8. System records response time and sends confirmation notification to Customer. |
| **Alternative Flows** | 1. **Reject booking**: At step 5, PT chooses Reject; System requires reason; PT submits; System sets `Rejected`, initiates refund if paid (BR-09), notifies Customer with reason. 2. **Already processed**: At step 6, booking no longer Pending; System shows current status and does not overwrite. |
| **Exceptions** | 1. **Response deadline passed** (`after(24h)` / BR-08): System auto-sets `Cancelled`, initiates refund if applicable, notifies Customer and PT. 2. **Missing rejection reason**: Reject without reason → validation error; status unchanged. 3. **Refund not completed immediately**: Gateway delay/fail → refund recorded as Pending + ops alert; booking remains Rejected. |
| **Priority** | High |
| **Frequency of Use** | High — every new PT booking requires a response. |
| **Business Rules** | BR-07: only Approved PT may process bookings. BR-08: respond within 24 hours or auto-cancel + refund. BR-09: reject requires reason; paid → refund process. Confirm and Reject are alternative flows of UC-12, not separate «extend» use cases. |
| **Other Information** | Related: UCD PT; AD-01 (pending); SMD-02; Wireframe SCR-12 `UI_UC12_PTBooking.png` (UI reference — not a VP diagram). |
| **Assumptions** | System clock is synchronized (UTC+7) for the 24-hour rule. |
